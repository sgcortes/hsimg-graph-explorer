# HSIMG Graph Explorer

[Public application](https://sgcortes.github.io/hsimg-graph-explorer/)

A browser application for loading, visualizing and checking the spatial mobility
graphs generated by IFC2GRAPH. GeoPackages are processed locally with SQL.js /
WebAssembly; uploaded files are not sent to a server.

## Explorer

- Interactive 3D graph with rotate, pan, zoom and selection.
- 2D floor plan with IfcSpace boundaries and a building-level selector.
- Independent visibility controls for nodes, connections and spatial context.
- Internal subgraphs for mobility spaces and surroundings for destination spaces.
- Node metadata, graph statistics and resizable panels.

## Validation

The **Validation** tab shares the loaded dataset but keeps an independent map,
floor, selection and filters. **Doors**, **Stairs** and **Elevators** have separate
visibility switches, alongside **Context graph**. Switches persist across floors.

Checks cover space and door connectivity, stair/elevator/ramp exits to floors,
vertical continuity, internal dead ends, invalid connections and exact duplicates.
The inspector provides evidence, interpretation, suggested review and criteria.

Service shafts and construction zones are intentionally outside the default
required-access scope. They remain grey and listed, but do not count as access
failures or true negatives and cannot serve as transit in exterior route analysis.
**Review excluded spaces** opens their cases; **Access requirement** in the
inspector allows each exception to be included or excluded explicitly.
Missing doors alone never justify an automatic exclusion.

**Access from exterior doors** colours spaces by directed reachability for general
or wheelchair mobility. All exterior origins remain listed. Percentages use only
required destinations; excluded spaces are reported separately.

Case and metrics tables export to CSV. Independent anomaly/normal review labels
enable TP, FP, FN, TN, precision, recall and F1. Without independent references,
accuracy metrics are not calculable. Review passing cases too to identify false
negatives. Reference JSON binds labels to dataset SHA-256, validator version,
profile and scope. Scope changes clear labels because route outcomes may change;
export a review before changing scope if you need to retain it.

See [validation criteria, results and limits](docs/VALIDATION.md).

## Included model

The app loads `EPM_IFC_v13_HSIMG_v14.gpkg`, generated from
`13_EPM_IFC4_SpaceBoundary (2).ifc` using HSIMG V14. IFC revision v13 and generator
version V14 refer to different things.

V14 removes horizontal branches that do not participate in shortest paths between
access points, preserves routes for general and wheelchair profiles, and stores
intermediate shape points as polyline vertices. Curves around obstacles remain.
The `horizontal_cleanup_v14` table records the cleanup audit;
`public/graph-manifest.json` provides SHA-256 hashes and inventory counts.
The reduced graph is intended for routing between access points. Redundancy
analysis requires an export with `--keep-all-horizontal-alternatives`.

## Supported formats

- **GeoPackage (`.gpkg`), recommended:** graph tables, floors, space polygons,
  door inventory and vertical elements. Architectural context uses IfcSpace
  boundaries; the current exporter does not include an IfcWall layer.
- **JSON / GeoJSON:** NetworkX node-link graphs using `nodes` and `edges` or
  `links`. Floor context and complete validation need corresponding inventories
  and geometry; graph-only files display completeness warnings.

## Local development and verification

Requires Node.js 22.13 or later and pnpm 11.25.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm exec tsc -p tsconfig.app.json --noEmit
pnpm test:graph
pnpm test:validation
pnpm test
pnpm build:github
```

The development server prints its local URL, usually `http://localhost:3000`.
The Pages workflow verifies the bundled GeoPackage, runs graph and validation
checks, and builds the public app. Keep `public/sql-wasm.wasm` matched to the
installed SQL.js version when deploying. `pnpm build` builds the server variant.
